# Agent Instructions

## Project Overview

SleepingServerStarter is a Node.js and TypeScript service that starts a Minecraft server when a player attempts to connect. It also provides a web interface, Discord notifications, and Docker and panel deployment support.

- Requires Node.js 22+ and npm 10+ (`package.json` engines).
- `src/` is the TypeScript source of truth. `build/` is generated by TypeScript and contains runtime views; do not edit generated JavaScript by hand.
- `sleepingSettings.yml` is the primary configuration file. `server.properties` can override selected settings when `useNativeFiles` is enabled.
- `src/sleepingContainer.ts` coordinates service startup. Java and Bedrock listeners implement `ISleepingServer`.

## Protocol Scope

- Java protocol code and tests live in `src/java/`. The listener implements only TCP handshake, server status and ping, and login-start handling. It disconnects clients to prompt server startup; it is not a Minecraft world server and does not authenticate accounts.
- Bedrock protocol code and tests live in `src/bedrock/`. The listener implements RakNet discovery and the connection handshake, then disconnects at `NEW_INCOMING_CONNECTION`. It does not implement Bedrock world login or gameplay.
- Keep protocol changes dependency-free unless the task explicitly requires a protocol library. Preserve packet framing and response behavior with focused protocol tests.
- Keep player access decisions in the existing access-checking flow. Java identity is an offline UUID; do not treat the supplied username as authenticated account identity.

## Development And Validation

- Install locked dependencies with `npm ci`.
- Type-check/build TypeScript with `npm run build:typescript`.
- Run all tests with `npx jest --runInBand`; there is no `npm test` script.
- Add or update focused tests when changing packet parsing, response encoding, connection state, or wake-up behavior. Tests live beside their source in `src/` and use Jest with `ts-jest`.
- `npm start` runs `prebuild`, which removes and recreates `build/` and `bin/`, then launches the application. Avoid it for routine validation.
- `npm run lint` uses ESLint with `--fix`; check that an ESLint 9 configuration exists before running it, and prefer targeted formatting over formatting the entire repository.

## Change Guidance

- Follow the existing TypeScript style and strict compiler settings in `tsconfig.json`.
- Keep changes scoped to the owning source modules, tests, and relevant documentation. Update `package.json` and `package-lock.json` together when dependencies change.
- Preserve user changes, including staged changes and generated files; inspect `git status` before broad commands and do not reset or clean the worktree.
- Update `README.md` when configuration, supported protocol behavior, or runtime requirements change.
